- [배포와 운영 검증](deployment.md): 폐기용 A/B 계정의 운영 검증 73건 통과.

- 설명서: [여섯 항목 인증 구현 설명서](authentication.md).

## 짧은 확인 방법 4줄

1. 어디로 가나요: 과제7 앱 주소와 public 소스의 이 문서·검증 결과를 엽니다. 소스 URL은 연결 후 확정합니다.
2. 세 단계 안에 무엇을 하나요: 앱의 로그인 첫 화면 확인 → 소스의 검증 결과 열기 → 같은 요청의 성공·거절과 소스 위치 대조. 심사자가 실제 계정을 만들거나 실제 비밀번호를 받을 필요가 없습니다.
3. 무엇이 보이면 통과인가요: 로그인 첫 화면은 열리고 개인 자료는 익명 API 401, 다른 계정 자료 404, 로그아웃 뒤 같은 인증값 401이며 문서와 코드가 맞습니다. 실제 5일 항목은 사용 후 별도 근거를 추가해야 합니다.
4. 안 될 때는 무엇이 보이나요: 잘못된 로그인은 동일 안내 문구, 세션 만료는 재로그인 창, 접근 거절은 오류 응답, 저장/이전 실패는 입력 유지와 재시도 안내가 보입니다.

## AI와 내 판단 3줄

1. AI에게 맡긴 일: 과제 분석, T06 계승, 인증·소유권·자료 이전·실험·계정 관리 구현과 로컬/브라우저 검증·문서 정리.
2. 내가 직접 판단한 일: 필수 단계 전체와 UX A1~A7 승인, 기존 기능·자료 보존과 구현·검증·실제 사용 절차 정리 요청. 실제 질문·지표·규칙·행동·해석은 내가 정합니다.
3. AI 제안을 따르지 않은 일: 현재 과제7 대화에서 확인된 사항 없음. 이후 실제 사용에서 바꾼 판단과 이유를 추가합니다.
