# 과제7 구조와 책임

현재 실행 소스는 과제6에 인증·소유권·이전·실험·계정 관리를 구현한 과제7입니다. 실제 검증 결과는 evidence/verification-results.md에 있습니다.

## 계승 원칙

기존 `app`, `src`, `db`, `drizzle`, `contracts`, `tests`, `scripts`, `worker`의 책임을 유지합니다. 구조 정리만을 위해 작동하는 과제6 기능을 다시 작성하지 않습니다. 프레임워크·DB 변경은 이번 구조 작업에 포함하지 않습니다.

| 위치 | 역할 |
| --- | --- |
| `app` | 로그인·가입·설정·실험 화면과 API 진입점. UI에 서버 비밀값을 전달하지 않음 |
| `src/features` | 기존 계획·할 일·실행·회고·오늘과 신규 인증·자료 이전·실험·계정 UX |
| `src/components/ui` | 폼·대화상자·오류·상태 안내 공통 UI |
| `src/server/auth` | 가입·로그인·로그아웃·비밀번호 변경·만료·인증값 폐기 |
| `src/server/access-control` | 인증된 계정 기준 소유자 검증·권한 거절 |

## 구현할 경계

화면 요청 → API → 서버 인증 → 소유권 확인 → 계정 범위 DB 처리 → 응답 순서로 설계합니다. 인증 화면 리다이렉트와 API의 미인증 거절은 각각 확인합니다.

사용자가 보낸 URL·헤더·본문의 계정 ID를 소유권 근거로 사용하지 않습니다. 목록·단일 자료·수정·삭제·집계·타이머·수정 이력·내보내기·중복 요청 처리에 같은 계정 경계를 적용합니다. 자식 자료 ID와 부모 계획·할 일 ID가 다른 계정에 속한 경우도 거절합니다.

인증 방식과 라이브러리 선택은 [인증 구현 설명서](authentication.md)에 비교 이유와 버전을 적은 뒤 구현합니다. 계정·인증값·자료 소유 관계·실험 설정에 필요한 테이블과 제약은 `db/schema.ts` 및 `drizzle`에서 추가합니다. db/auth-schema.ts와 db/experiment-schema.ts 및 drizzle/0001_orange_aaron_stack.sql에 실제 선언·마이그레이션을 추가했습니다. 기존 T06 SQL은 보존했습니다.
