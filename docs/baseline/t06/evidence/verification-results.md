## 브라우저에서 확인한 흐름

1. 검증용 계획 작성 → 서버 DB 저장 → 계획 수정 → 최초 v1·수정 v2의 전후 비교
2. 할 일 빠른 추가 → 제목만 비워지고 계획·태그가 유지됨
3. 스크립트 형태 제목이 문자 그대로 표시되고 해당 스크립트 노드가 생성되지 않음
4. 타이머 시작 → 새로고침 → 시작 시각·경과 시간 복원 → 종료 시 실행 기록 생성 → 실제 시간을 2분으로 수동 보정
5. 돌아보기에서 예상 60분·실제 47분·차이 -13분 확인 → 숫자를 눌러 할 일별 근거 표 확인
6. 개선점 저장 → 다음 계획 도우미에서 할 일 1개 선택 → 새 계획에서 개선점과 미완료 할 일 확인. 과거 실행 기록은 복사되지 않음
7. 할 일 삭제 → 실행 취소 → 원래 할 일 복원
8. 태그 11개 입력으로 서버 검증 오류 유도 → 제목과 태그 유지·태그 입력으로 초점 이동 → 태그 수정 후 정상 저장
9. 390px 모바일 폭에서 탐색 메뉴·돌아보기 동작 확인. 문서 폭 390px로 가로 넘침 없음

위 테스트는 로컬 개발 DB에서만 수행했습니다. 검증용 계획과 기록을 공개 배포 DB에 넣지 않습니다.
