# 구조와 데이터 설계 방향

React 19·TypeScript와 Sites 공식 Vinext starter로 구현한 단일 웹 앱입니다. Cloudflare Worker의 API와 D1(SQLite)를 사용하며, Drizzle은 스키마·마이그레이션 생성에 사용합니다. DB 요청은 서버에서 매개변수 SQL과 원자적 batch로 처리합니다.

## 폴더 책임

| 위치                      | 책임                                            |
| ------------------------- | ----------------------------------------------- |
| `src/features/plans`      | 계획, 수정 이력, 변경 비교                      |

## 데이터 관계 초안

- 계획은 여러 할 일과 여러 수정 이력을 가집니다. 수정해도 계획 ID는 유지합니다.
- 할 일은 하나의 계획에 속하며 여러 실행 기록을 가질 수 있습니다.
- 실행 기록은 계획의 예상값과 별도 보존합니다.
- 돌아보기는 대상 기간·계획·개선점과 다음 계획 연결을 서버에 보존합니다. 화면의 수량·시간은 대상 원본 자료로 계산합니다.
- 중복 요청의 식별 정보는 완료 처리 결과와 함께 보존합니다.

실제 테이블은 plans, plan_revisions, tasks, executions, timers, completions, reviews, commands입니다. 최종 정의는 `contracts/pds-schema-v2.json`에 있습니다.

## 구현 기본안

아래는 과제 원문이 세부 방식까지 정하지 않은 부분에 적용한 구현 규칙입니다. 스키마 계약과 검증 사례로 확인합니다.

- 기간 조회는 할 일의 마감일을 기준으로 합니다. 선택된 할 일의 모든 실행 기록을 시간 합계에 포함하고 이 기준을 화면에 표시합니다.
- 마감일·계획 기간은 날짜로 저장합니다. 실행 시각은 UTC로 저장하고 서울 시간으로 표시합니다.
- 소요 시간의 저장·집계 단위는 분입니다. 타이머는 올림해 최소 1분으로 계산하고, 직접 수정한 양의 정수 분을 실제 시간으로 보존합니다.
- 동일 정렬값은 생성 시각과 고유 ID로 순서를 확정합니다.
- 삭제는 논리 삭제를 사용합니다. 삭제한 할 일과 그 실행 기록은 현재 돌아보기에서 제외하며, 복원 시 다시 포함합니다. 전체 내보내기에는 삭제 표시와 보존 이력도 포함합니다.
- 완료 취소는 현재 상태만 바꾸고 과거 실행 기록을 지우지 않습니다.
- 완료 처리에는 요청 식별 키·DB 제약·트랜잭션을 사용합니다. 같은 요청의 재전송과 이미 완료된 항목에 대한 추가 완료 요청은 새 완료 기록을 만들지 않습니다. 완료 취소 후 정당한 재완료는 별도 상태 전이로 처리하고, 완료 수는 현재 상태를 기준으로 합니다.
- 타이머는 경과 초를 계속 더하는 대신 저장한 시작 시각을 기준으로 복구합니다. 서버 저장에 실패하면 저장되지 않았음을 분명히 표시합니다.
- 내보내기는 계획·수정 이력·할 일·실행 기록·돌아보기·개선점 관계, ID, 날짜·단위를 보존하는 단일 JSON 파일을 기본안으로 합니다. 비밀키와 내부 설정은 제외합니다.

최종 DB 계약과 마이그레이션이 다르면 구현 완료로 보지 않습니다.
