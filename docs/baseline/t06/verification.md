# 검증 안내와 재확인 체크리스트

구현과 검증은 완료했으며, 수행한 범위와 관찰 결과는 [검증 결과](evidence/verification-results.md)에 기록했습니다. 아래 체크박스는 이후 변경 시 재확인할 목록입니다. 본인의 실제 회고·다음 계획 작성은 [과제 제출 문서](submission.md)의 남은 실제 사용 항목을 참고하세요.

## 필수 검증

- [ ] 계획의 필수값을 저장하고, 두 번 수정해도 최초·중간·현재 내용을 구분할 수 있다.
- [ ] 할 일의 생성·수정·완료·완료 취소·삭제가 DB와 화면에 일치한다.
- [ ] 검색·필터·정렬이 화면에 표시된 기준대로 작동하고 동률 순서가 안정적이다.
- [ ] 실행 기록의 시각·시간·막힌 이유와 할 일 연결이 저장되고 원래 계획값은 유지된다.
- [ ] 완료 연속 클릭·같은 요청 재전송·동시 요청에도 완료 기록과 집계가 한 번만 증가한다.
- [ ] 완료 취소 후 재완료는 현재 상태에 맞게 집계되며 이전 실행 기록은 보존된다.
- [ ] 빈 자료의 수량·시간은 0이고 예상 30분·실제 45분의 차이는 +15분이다.
- [ ] 오늘 마감은 지연이 아니고, 어제 마감의 미완료만 지연이다. 서버 시간대가 달라도 서울 날짜 기준이 같다.
- [ ] 완료·삭제한 할 일은 지연에 포함되지 않는다. 논리 삭제한 할 일과 연결 실행 시간은 집계에서 제외된다.
- [ ] 같은 할 일의 실행 기록 여러 건에 막힌 이유가 있어도 막힘 수는 1이다.
- [ ] 모든 집계 숫자의 근거 목록이 동일한 기간·필터와 계산 기준을 사용한다.
- [ ] 개선점 한 건과 원래 돌아보기의 연결이 다음 계획에서 확인된다.
- [ ] 본인의 실제 계획 1개·할 일 5개·실행 기록 3개 이상이 있고 돌아보기 값이 모두 0은 아니다.
- [ ] 새로고침 후 ID·날짜·값·단위가 같고 브라우저 저장소만으로 영속성을 대신하지 않는다.
- [ ] 전체 자료를 파일 하나로 내보내 관계·수정 이력·삭제 표시·단위가 보존된다.
- [ ] 실제 DB와 마이그레이션, `contracts/pds-schema-v2.json`이 일치한다.

## A·B UX 검증

- [ ] 오늘·지연·진행 중 화면의 분류가 원본과 일치한다.
- [ ] 빠른 추가가 유지해야 할 항목만 유지한다.

- [ ] 삭제 실행 취소 시 연결 기록과 집계가 복원된다.
