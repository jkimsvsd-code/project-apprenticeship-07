# 기존 자료를 계정으로 이전하기

상태: A2 구현·기존 브라우저 검증 및 본인 계정의 실제 자료 이전 완료. 2026-10-28 반복 업로드·날짜·파일 크기 제한을 보완했습니다. [보안 보완 검증](evidence/import-hardening.md)

## 순서

1. 과제6 최종 제출 커밋과 이전할 원본 데이터의 기준 시점을 확인합니다.
2. 본인이 확인한 대상 계정을 지정합니다. 첫 가입자에게 기존 자료를 자동 귀속시키지 않습니다.
3. 원본은 Git 제외 위치에 백업하고 계획·할 일·실행·타이머·완료·회고·수정 이력·중복 요청 처리 자료를 조사합니다.
4. 대상과 건수, 연결 관계, 시간 합계를 미리 보여 줍니다. 원본의 비밀값이나 타 계정 자료는 화면에 노출하지 않습니다.
5. 일회성 이전을 수행하고 같은 원본을 재시도해도 중복 생성·잘못된 재귀속이 없게 합니다.
6. 이전 후 건수·ID 관계·실행 시간 합계·회고/다음 계획 연결·소유자 없는 자료 여부를 대조합니다.
7. 다른 계정이 이전된 자료를 읽거나 수정·삭제·목록 조회·내보내기 할 수 없는지 검증합니다.

## 구현할 보장

- 자료의 소유자는 서버에서 확인한 지정 계정으로 고정합니다.
- 이전 전후 수량·합계와 실패 시 복구/재시도 결과를 기록합니다.
- 이전 ID와 완료 상태를 서버에서 관리해 중복 이전을 방지합니다.
- 실제 원본 데이터와 계정 매핑은 공개 저장소에 포함하지 않습니다.
- 이전 기록은 과제7의 잠긴 앱에서 새로 수행할 실제 5일 기록과 구분합니다.

소스 위치: `src/features/migration`, `src/server/migration`, `app/api/import`. 검증 위치: `tests/integration/migration`. POST /api/import의 preview/import를 구현했습니다. 원본 내용은 허용한 필드만 읽고 계정별로 ID를 다시 매핑하며 이전 관계와 시각을 보존합니다.

## 서버 제한

- 로그인한 계정마다 서버 기준 60초 고정 구간당 preview/import 요청 합계 12회. 초과 시 429와 `Retry-After`를 반환합니다. DB의 계정당 한 행을 사용해 Worker 교체·재시작과 동시 요청에도 제한을 공유합니다.
- 계정당 서로 다른 원본 파일 최대 5개, 누적 20,000건. 기존 이전 영수증도 포함하며 성공한 원본의 건수만 누적합니다. 같은 파일 재시도는 추가 차감하지 않지만 요청 빈도 제한은 적용됩니다. 파일 내용을 바꾸면 새 원본으로 계산합니다.
- 파일 하나는 최대 2,000,000바이트, 테이블별 5,000건·전체 10,000건입니다. 요청에는 JSON 감싸기용 128바이트만 추가 허용합니다. 서버는 헤더를 믿지 않고 실제 읽은 바이트를 세어 초과 시 즉시 취소합니다.
- 달력 날짜는 실제 존재하는 `YYYY-MM-DD`, 시각은 과제6이 내보내는 `YYYY-MM-DDTHH:mm:ss.SSSZ`입니다. 종료일/종료 시각이 시작보다 빠르거나 수정 시각이 작성 시각보다 빠르면 거절합니다. 원래 유효한 문자열과 원본 해시는 바꾸지 않습니다.
- DB 트랜잭션 안에서 한도·중복 여부를 검사하며 영수증을 먼저 확보한 요청만 자료를 삽입합니다. 실패하면 영수증·자료가 함께 되돌려져 재시도할 수 있습니다.

누적 한도는 이전 영수증 기준이므로 가져온 계획을 나중에 삭제해도 다시 늘어나지 않습니다. 이 제한은 계정별 방어이며 새 계정의 대량 생성까지 차단하는 전역 방어를 의미하지 않습니다. 과제6 공개 원본의 접근 설정은 바꾸지 않습니다.
