실제 요청과 응답은 [http-results.json](authentication/http-results.json)에 있습니다. `cookie-ref-N REDACTED`는 실행 중 같은 원문 쿠키에 붙인 비공개 별칭으로, 원문을 공개하지 않고 로그아웃 전후 같은 값을 재사용했음을 대조합니다. 원문 쿠키와 비밀번호는 기록하지 않았습니다. 저장 해시는 종료 시 삭제한 폐기용 계정의 값입니다.

## 확인한 서버 경계

- 로그인 화면 200, 미로그인 자료 화면 307 로그인 이동, 직접 API는 401.
- 정상 가입·로그인·중복 가입 거절, 없는 계정과 틀린 비밀번호의 상태/문구 동일.
- 같은 임시 비밀번호의 서로 다른 scrypt 저장값, 비밀번호 원문 비노출, HttpOnly 쿠키.
- 본인 읽기·수정·삭제·복원 성공, A→B/B→A 읽기·수정·삭제 모두 404.
- 거절 전후 상대 자료 내용·건수 동일. 다른 계정의 부모 계획·타이머 대상 ID도 거절.
- URL·헤더·본문의 소유자 위조를 무시하고 본인 자료만 반환/생성. 익명 위조는 401.
- 목록·관련 자료·내보내기 분리, 교차 출처 쓰기 403, 계정별 중복 요청 ID 분리.
- 같은 GET·같은 기존 쿠키로 로그아웃 전 200, 뒤 401. 비밀번호 변경 전 쿠키도 401, 새 쿠키는 200.
- DB 만료 시각을 지난 테스트 세션은 401.
- 틀린 비밀번호의 계정 삭제 거절, 올바른 삭제 뒤 계정·자료·세션 제거, 다른 계정 자료 그대로 유지.
- 이전 자료의 관계·내용·시각·합계 보존, 같은 파일/내보내기 시각 변경에도 중복 없음, 잘못된 파일과 DB 제약 실패 시 전체 되돌림.
- 5개의 서로 다른 서울 날짜, 2일차 뒤/3일차 전 규칙 변경 1회, 참조 ID 보존, 중복 날짜·순서 위반·6번째 기록 거절.
- 원값 합계 후 마지막 반올림, 앞 2일/뒤 3일 각각 다른 분모로 같은 기준 계산.

## 남은 실제 작업과 한계

- 2026-10-27 운영 DB에서 본인 계정 가입·실제 자료 이전과 실험 설정 저장을 확인했습니다. 실제 일별 기록은 0/5일, 규칙 변경은 0/1회이며 실제 날짜 5일 사용·규칙 변경·실제 값 수동 검산은 남아 있습니다. [완료 확인 근거](completion-review.md) · [절차](../five-day-guide.md)
- 자동 테스트는 가상 날짜를 함수 인자로 주입했으며 브라우저/공개 API에는 날짜를 바꾸는 기능이 없습니다.
- 2026-10-27 사용자 명시 승인 후 Sites 소스 전송·공개 배포를 완료했습니다. 개인 백업·비밀값·전체 비밀번호 해시는 제외했습니다. 운영 검증 결과는 아래 별도 항목에 기록합니다.
- [GitHub public 소스](https://github.com/jkimsvsd-code/project-apprenticeship-07)를 공유합니다. 2026-10-27 과제6 기준 커밋과 공개 main의 일치·과제7 조상 포함을 확인했고 사용자가 실제 제출본임을 확인했습니다. 실제 5일 사용과 수동 검산·제출 근거는 남아 있습니다. GitHub Actions 결과는 해당 실행에서 확인하며 기존 로컬/운영 검증과 구분합니다.
- 인증/소유권을 로컬 실제 Worker에서 검증했으며 별도의 외부 보안 감사나 부하·다중 리전·모든 브라우저/기기 검증은 수행하지 않았습니다. 반응형 스타일을 구현했지만 모바일 실제 기기 결과로 표시하지 않습니다.
- 이메일 확인·비밀번호 찾기·MFA·분산 무차별 대입 방어와 계정 복구는 제공하지 않습니다. 자세한 위험은 [설명서 ⑥](../authentication.md)에 있습니다.

공개 증거의 저장 해시는 일부만 표시합니다. 실제로 비교한 폐기용 계정의 전체 해시는 Git 제외 파일 `.local/qa-password-hashes.json`에만 보관하며 원문 비밀번호는 보관하지 않습니다.

## 배포 후 운영 검증

사용자 승인 후 과제7 전용 Sites 원격 소스 저장소에 전송하고 공개 배포했습니다. 대상은 [과제7 앱](https://pds-diary-apprenticeship-07-m2021.happybay512.chatgpt.site)입니다. 운영 코드 검증 기준 커밋은 `590e291e078840891d854c05f6657b00a45aa871`입니다.

[운영 요청·응답 증거](authentication/deployment-http-results.json) **73건이 모두 통과**했습니다. 운영 확인은 폐기용 A/B 계정으로 수행했으며 생성한 계정·자료와 임시 로컬 인증 파일은 모두 삭제했습니다. 사용자의 실제 계정이나 과제6 원본 자료는 테스트 대상으로 사용하지 않았습니다.

- 로그인 화면 200, 익명 첫 화면은 로그인으로 307, 자료·내보내기·실험·세션 API는 401.
- 가입·로그인·중복 가입 거절, 없는 계정과 틀린 비밀번호의 동일 응답.
- HTTPS 쿠키 Secure·HttpOnly·SameSite=Lax와 7일 만료 시각 확인.
- A/B 각각 본인 화면·자료만 표시. B HTML에 A 신원 정보가 없고 인증 요청 뒤에도 익명 화면은 로그인으로 이동.
- 양방향 타 계정 읽기·수정·삭제 및 다른 계정 부모/타이머 ID는 404. 거절 전후 상대 내용·건수 동일.
- URL·헤더·본문 계정 위조, 익명 신원 헤더 위조, 교차 출처 쓰기, 서명 변조 쿠키 차단.
- 본인 수정·삭제·복원·내보내기 성공. 내보내기에 다른 계정 자료와 인증값 없음, 응답 no-store.
- 같은 GET·같은 기존 쿠키로 로그아웃 전 200/뒤 401. 비밀번호 변경 전 쿠키 401/새 쿠키 200.
- 잘못된 비밀번호의 삭제 거절, 자기 계정 삭제 후 세션 401, 다른 계정 자료 보존.

운영에서 실제 7일을 기다려 만료를 관찰하지는 않았습니다. 만료 시각은 운영에서 확인했고, 만료 뒤 거절은 별도 로컬 실제 Worker 테스트에서 확인했습니다. 실제 5일 사용을 완료한 것으로 표시하지 않습니다.
