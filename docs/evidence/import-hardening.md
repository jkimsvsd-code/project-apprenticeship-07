요청 제한 테이블은 계정당 한 행이므로 요청 수만큼 무한히 늘어나지 않습니다. 원문 쿠키나 IP를 저장하지 않으며 계정 삭제 시 외래키 cascade로 제거합니다. 누적 한도는 기존 imports 영수증에서 계산하므로 배포 시 이전 계정의 사용량을 초기화하지 않습니다. 실패한 트랜잭션은 영수증·자료를 함께 되돌립니다.

- TypeScript 검사, 단위/SQLite 통합 30개(새 보안 사례 8개), 스키마 계약 검사, 공식 Sites 프로덕션 빌드 통과.
- 실제 로컬 Worker/D1 가져오기 HTTP 검사 24건 통과. 합성 fixture와 폐기용 계정만 사용했고 두 계정을 삭제한 뒤 이전 인증값 401까지 확인.
- 기존 실제 로컬 Worker 인증·소유권 HTTP 검사 61건 회귀 검증 통과. 기존 공개 증거 파일은 보존.
- 개인 보관 중인 과제6 원본은 메모리 DB에서만 확인. 계획 2·이력 2·할 일 5·실행 3·회고 1·합계 75분, 기존 운영 영수증 해시 일치, 재시도 중복 방지 확인. 원본 파일·내용·계정 ID·원본 해시는 공개하지 않음.
- CI에 실제 로컬 Worker 가져오기 검사를 추가. `npm run test:http:import`로 재현. 미검토 실행 증거는 `.local/`에만 생성.

## 운영 반영 상태와 남는 범위

Sites의 공식 소스 도구에 단기 저장소 자격증명을 숨겨진 stdin으로 전달하는 단계가 자동 승인 검토에서 거절됐습니다. 거절 사유는 샌드박스 밖 터미널로 인증값을 전달할 때의 자격증명 노출·관리형 네트워크 통제 우회 위험입니다. 이 경로를 우회하지 않았으며, 운영 배포가 끝나기 전에는 새 제한이 운영에 적용됐다고 판단하지 않습니다. 승인 후 동일 소스를 전송·배포하고 폐기용 계정으로 운영 경계를 다시 확인해야 합니다.

과제6 공개 사이트의 원본·Git 이력은 이번 범위에서 변경하지 않습니다. 계정 생성 자체의 대량 남용, 이메일 확인·MFA·전역 분산 방어까지 해결한 것은 아닙니다. 실제 5일 사용이나 개인 기록의 값·시각도 변경하지 않았습니다.
