# 검증 계획

상태: 구현과 로컬 검증 완료. 실제 관찰 결과와 증거는 [검증 결과](evidence/verification-results.md)에 있습니다. 아래는 범위별 검증 규약입니다. 기존 과제6 결과는 [보존 자료](baseline/t06/evidence/verification-results.md)에 있습니다.

## 다섯 증거 묶음

| 묶음 | 정상 사례 | 거절·비노출·보존 사례 | 증거 폴더 |
| --- | --- | --- | --- |
| 가입·접근 | 정상 가입·로그인·본인 자료 조회 | 중복 가입, 잘못된 비밀번호/없는 계정의 동일 문구, 미로그인 화면·API | `evidence/authentication` |
| 비밀번호 | 테스트 계정 생성과 저장 형태 확인 | 원문 비노출, 같은 비밀번호의 서로 다른 저장값 | `evidence/passwords` |
| 인증값 | 유효한 값으로 동일 API 성공 | 로그아웃·만료·비밀번호 변경 후 이전 값 거절, URL·코드·로그 비노출 | `evidence/sessions` |
| 계정 분리 | A와 B 각각 본인 자료 읽기·수정·삭제·목록 | A→B와 B→A의 읽기/수정/삭제 6개, URL/헤더/본문 위조, 미로그인, 목록 혼입 없음 | `evidence/ownership` |
| 자료 관리 | 본인 전체 내보내기·지정 계정 삭제 | 타 계정 자료 미포함·변경 없음, 삭제 범위·실제 처리 일치 | `evidence/data-management` |

과제의 '확인 다섯 가지'를 누락 없이 설명하기 위한 구성입니다. 비밀번호 검증은 저장 형태와 비노출 증거로 남기고, 관련 요청이 있는 검증은 정상 요청과 거절 요청을 함께 적습니다.

각 증거에는 수행 시각·코드 커밋·API 주소·HTTP 방식·마스킹한 헤더/본문·응답 상태/내용·관련 소스 위치·확인한 결과를 적습니다. 화면 제한과 실제 HTTP 접근 제한은 따로 확인합니다.

로그아웃 전후 비교는 주소·방식·인증값을 동일하게 유지합니다. 마스킹 표시도 같은 식별표기를 사용하되 원본은 공개하지 않습니다. 계정 간 거절 전후 건수·내용과 새 자료 생성 여부를 확인합니다. 다른 계정의 부모/자식 ID를 섞는 요청, 수정 이력·타이머·집계·중복 요청 ID 재사용·내보내기도 검사합니다.

## UX 검증

| 항목 | 검증할 사용자 흐름 |
| --- | --- |
| A1 | 표시 전환·자동완성·키보드·오류 안내, 비밀번호가 다른 UI나 저장소에 남지 않음 |
| A2 | 이전 미리보기·대상 확인·건수 대조·중복 이전·중간 실패 재시도 |
| A3 | 실험 설정 순서·필수값 안내·설정 고정·실제 날짜별 진행 현황 |
| A4 | 2일차 완료 뒤 안내·3일차 전 변경·규칙 하나·변경 시각/이유/참조 보존 |
| A5 | 변경 전 2일/후 3일 구분·같은 단위/계산·일별 근거·합계/평균 검산 |
| A6 | 만료 후 원래 화면 복귀·안전한 내부 이동 경로·같은 계정 입력 복구·비밀번호 제외·계정 전환 격리 |
| A7 | 내보내기 범위·실패/성공 안내·삭제 전 범위/복구 안내·삭제 후 인증값과 자료 처리 |

## 실제 사용과 제출

인증과 소유권 검증 후 실제 5일 사용을 시작합니다. 날짜·지표·계산 규칙·규칙 변경 순서·합계·평균은 [실험 규약](experiment.md)을 확인합니다. 테스트용 날짜 변경이나 자동 생성 자료로 실제 사용을 대신하지 않습니다.

마지막으로 시크릿 창에서 결과물 로그인 첫 화면과 public 소스가 초대·추가 인증 없이 열리는지, 개인 기록은 열리지 않는지 확인합니다. 증거 마스킹·Git 이력 비밀값·최종 기준 커밋·제출 설명과 실제 코드의 일치를 확인합니다.
